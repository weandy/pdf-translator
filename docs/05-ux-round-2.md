# 体验改进第二轮：设计

> 日期：2026-10-29
> 来源：用户体验走查（全新浏览器走完首次使用 → 上传 → 等待 → 阅读 → 修改 → 下载 → 再次回来），见各节“依据”。
> 范围：设置面板、上传确认、按钮位置、操作提示、分段加载与下载、目录侧栏、键盘操作、公式编辑、24 小时保留、重复上传提醒。

---

## 1. 设置面板：两步开始

**依据**：面板高 1470 px（屏幕 900 px），11 个选项，MinerU Token 要往下滚才看到。

**设计**
- 顶部“开始使用只需两步”：
  1. 翻译服务 API Key：附 DeepSeek 获取链接；填完失焦时自动测试连接，结果显示在旁边。“用其他服务（接口协议、地址、模型）”折叠，默认收起。
  2. MinerU Token：附获取链接与额度说明。
- “翻译偏好”（翻译方式、参考文献、对照方向、记住 Key）折叠为一组，默认收起。
- 验收：首次打开（折叠状态）面板高度 ≤ 屏幕高度 900 px。

## 2. 上传确认只勾一次

**依据**：每次上传都要勾“我知道文件会上传到 MinerU”。

**设计**：勾选后记在浏览器设置里（`cloudConsent`），以后默认勾上；说明文字保留，取消勾选也会记住。后端仍要求 `cloud_consent=true`。

## 3. “开始翻译”按钮完整可见

**依据**：900 px 高的屏幕上，选好文件后按钮只露出一半。

**设计**：收紧上传栏的纵向间距（对开页示意图高度、说明框边距）。验收：1440×900 视口、选一个文件并显示页码范围后，按钮底边在视口内。

## 4. 操作提示

**依据**：阅读器里没有任何提示说明“点段落可以修改”，只有鼠标变成手形。

**设计**
- 阅读器首次打开时顶部显示提示条：点任意段落查看原文、修改、重翻、加入术语库；可用 Tab 键在段落间移动、回车打开；灰色虚线框是没通过校验的段落（点开重翻），黄色点线框是放不下已缩小的译文。“知道了”后不再自动显示（浏览器记住）。
- 工具栏“使用说明”按钮随时重新打开。
- 首页上传区下方加三步说明：选 PDF → 等解析和翻译 → 对照阅读、修改、下载。

## 5. 分段加载与下载

**依据**：打开一篇要下载 12.6 MB，其中两份 PDF 共 6.2 MB 被整份下载。

**设计**
- 阅读器：pdf.js 按需分段下载（`disableAutoFetch`、`disableStream`、`rangeChunkSize`=256 KB），只取当前看到的页需要的数据；服务器的文件接口已支持 HTTP Range（206）。
- 下载导出 PDF：导出结果按“任务 + 方式 + 译文状态”缓存成文件，用支持 Range 的文件响应返回，浏览器下载中断后可以续传；译文有修改时缓存自动失效（缓存键含段落内容的摘要）。
- 验收：打开阅读器首屏下载量明显下降（目标 ≤ 6 MB）；导出接口对 `Range` 请求返回 206。

## 6. 目录侧栏（以原文为准）

**设计**
- 目录来源以原文为准：优先用 PDF 自带的书签（`get_toc`，作者生成的目录最可靠）；没有书签时用解析出的标题块，按编号（“3.1” → 二级）估层级。
- 每项显示原文标题，下方小字显示译文（有译文时）。点击滚到对应页和位置；阅读视图里滚到对应段落。
- 工具栏“目录”按钮开关侧栏（桌面在左侧，窄屏从左侧滑出）；没有目录时按钮不显示。
- 顺带：工具栏显示“第 N / M 页”，可输入页码跳转；记住每篇文档上次读到的页，下次打开回到那里（浏览器本地）。
- 接口：`DocumentOut.outline: [{title, translated, level, page, top}]`。

## 7. 键盘操作

**设计**
- 译文段落（对照 / 译文视图的译文块、阅读视图的段落）可用 Tab 聚焦（`tabIndex=0`，`role="button"`，`aria-label` 为段落开头），回车或空格打开编辑；焦点有清晰的轮廓。
- 段落编辑与修改记录面板按 Esc 关闭，焦点回到原段落。

## 8. 公式编辑

**依据**：带公式的段落在编辑框里显示成 `<m1/>`，用户看不懂；保存时不检查，误删一个占位符，对应公式就从译文和导出 PDF 里消失。

**设计**
- 编辑框上方列出本段公式：`<m1/>` 对应渲染好的公式；点一下在光标处插入。
- 编辑框下方实时预览修改后的效果（公式正常渲染，与阅读器一致）。
- 保存前检查：每个公式占位符恰好出现一次、没有不存在的编号；不符合时不保存，提示“缺少公式 2（显示公式）”，并提供“插入到光标处”。
- 后端同样校验（接口直接调用也不会丢公式）：缺少或多出占位符返回 400。

## 9. 服务器只保留 24 小时

**设计**
- 保留时长改为按小时配置：`PDFTR_RETENTION_HOURS`（默认 24；0 表示不自动删除），替代 `PDFTR_RETENTION_DAYS`。
- 任务记录明确的到期时间 `expires_at`（创建时间 + 保留时长）；清理每 10 分钟执行一次，删除已到期的任务文件与记录。
- **已有的旧任务不立即删除**：没有到期时间的旧任务，在升级后第一次启动时设为“现在 + 24 小时”，留出下载时间。
- 译文缓存同样按保留时长清理（缓存里有译文内容，属于用户数据）。
- 界面提示：
  - 上传说明：“译文在服务器上保留 24 小时，之后自动删除，请及时下载”。
  - 我的任务：每项显示“还剩 N 小时”；
  - 阅读器：剩余不足 3 小时时提示“这篇译文将在 N 小时后删除，请先下载”。
  - 进度页、已完成页显示到期时间。
- 接口：`JobOut.expires_at`；`ConfigOut.retention_hours`。

## 10. 重复上传提醒（只在本机比对）

**隐私要求**：不与服务器上存的文件比对，指纹不发给服务器。

**设计**
- 选文件后在浏览器里计算文件指纹（SHA-256，Web Crypto 原生支持；比 MD5 更不易碰撞，作用相同）。
- 浏览器本地保存“翻译历史”：`{指纹, 文件名, 页数, 任务编号, 时间}`，最多 200 条，不随服务器 24 小时删除而删除，也不上传。
- 选中的文件与本地历史比对：
  - 命中且服务器上的任务还在：“这篇你在 10 月 29 日 14:05 翻译过（文件名）。[打开上次的译文] [仍要重新翻译]”。
  - 命中但服务器上已删除：“这篇你在 10 月 28 日翻译过，服务器上的译文已过期删除，可以在下载目录里找找当时下载的 PDF。[仍要重新翻译]”。
  - 只有用户点“仍要重新翻译”后才允许开始。批量上传时逐个标出“翻译过”，可单独移除。
- 首页“我的任务”下方增加“历史记录（仅本机）”，列出已过期删除的翻译（文件名、时间），可清除。
