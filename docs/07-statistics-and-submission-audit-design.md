# 统计页面与提交明细：设计方案

> 日期：2026-11-11
>
> 状态：实现与本地验证已完成；服务器发布结果另记验收报告。下文保留设计决策及发布边界。
>
> 范围：公开最近 7 天统计、跨日浏览器去重、管理员提交明细、标题与提交 IP 长期留存。
>
> 依据：用户确认的六项需求，以及本轮对源码和 HW-SGP 部署的只读核查。

## 1. 目标与边界

本轮产品设计落实以下六项要求：

1. 公开 `/stats` 固定展示最近 7 天，首页不放统计卡片。
2. 同时提供最近 7 天汇总、今日数据和最近更新时间。
3. 图表始终显示每天的日期和数值，支持手机点按、键盘选择。
4. 将“匿名访客”改为“访问浏览器”，说明它不等于实际人数。
5. 最近 7 天浏览器数按整个窗口去重，不累加每日浏览器数。
6. 论文标题与完整提交 IP 只在有后端鉴权的独立管理员页面展示，支持搜索、分页、日期筛选。

配套设计包括：可信提交 IP、长期提交账本、临时正文的清理边界，以及与真实行为一致的上传说明。

本轮不建设普通用户账号、多管理员角色、全站访问轨迹或第三方统计；不新增论文内容预览、管理批量下载、CSV 导出、IP 地理位置、自动封禁或成功率排名。管理员权限仅覆盖新管理接口，不宣称同时解决现有任务链接的所有访问控制问题。

## 2. 当前事实与问题

### 2.1 已有能力

- `/stats` 前端请求 7 天数据，首页没有统计概览。
- 后端已有每日访问、浏览器、提交任务、首次完成任务和完整上传 PDF 页数。
- 浏览器通过随机 UUID 上报访问；服务端保存 SHA256，不使用 IP 计算访问浏览器数。
- `analytics_visit_days(day, visitor_hash)` 足够计算当前 7 天的跨日去重。
- 任务统计与任务保存共用 SQLite 事务，重复保存、重试和删除不重复计数。
- 标题识别已存在，可复用 `paper_title()`；无需增加模型调用。

### 2.2 待改进项

- 公开接口仍允许 1～90 天、默认 30 天，并返回累计值，范围比页面要求更大。
- 页面没有 7 天汇总和更新时间；图表数值依赖悬浮提示，日期仅显示三个刻度。
- 没有管理员会话、提交标题账本或提交 IP 记录。
- 现有页面声明“不保存文件名或原始 IP”，实施后必须更新。
- 当前代理链没有完整的客户端 IP 信任配置，不能直接把现有请求地址当作提交者 IP。

### 2.3 服务器核查快照

2026-11-11 只读检查时：11 个任务、2065 条段落、2 条修改记录、2418 条翻译缓存；数据库约 4.6 MB，任务文件约 208 MB，另有 4 份数据库备份。未发现已过期任务行或孤立段落、修订。该快照仅说明检查时的状态，不是容量预测或清理机制已经完善的证明。

当前保留期为自上传起 24 小时，每 10 分钟扫描一次，仍在运行的任务跳过。数据库有短期原文、译文、修订和缓存；PDF、解析结果与导出在任务目录。

## 3. 信息架构

| 路由 | 使用者 | 内容 | 数据保护 |
| --- | --- | --- | --- |
| `/stats` | 所有访问者 | 最近 7 天聚合统计 | 无论文名、IP、任务 ID、浏览器标识 |
| `/admin/login` | 管理员 | 单一管理密码登录 | 不加载明细，不上报页面访问 |
| `/admin/submissions` | 已登录管理员 | 标题、IP、提交时间、页数、状态 | 每次 API 请求均验证管理员会话 |

顶部保留“统计”入口，不在首页增加统计展示。公开统计页底部提供低强调的“管理登录”文字链接；入口本身不构成保护。管理员页面采用独立布局，不展示翻译 Key 设置面板，也不计入公开 PV/浏览器统计。

## 4. 公开统计页设计

### 4.1 页面顺序

```text
访问与使用统计                         刷新数据
北京时间 · 11-05 至 11-11 · 更新于 14:32:10

最近 7 天（含今天）
访问次数 / 访问浏览器 / 提交任务 / 完成翻译 / 上传页数

今日 · 11-11（持续累计）
访问次数 / 访问浏览器 / 提交任务 / 完成翻译 / 上传页数

每日趋势                   查看指标：[访问次数 ▾]
七根柱：每根显示数值及日期
已选 11-11：访问次数 12

每日明细（可展开）
统计口径与数据保留说明                  管理登录
```

7 天范围是北京时间今天及之前 6 个自然日，包含尚未结束的今天；不是滚动 168 小时。不加累计历史、环比或成功率，避免范围和口径混淆。

### 4.2 指标名称与口径

| 字段 | 页面名称 | 今日值 | 7 天值 |
| --- | --- | --- | --- |
| `page_views` | 访问次数 | 当天页面打开、SPA 导航次数 | 窗口内每日 PV 之和 |
| `visitors` | 访问浏览器 | 当天 UUID 哈希去重 | 窗口内 UUID 哈希跨日去重 |
| `jobs_submitted` | 提交任务 | 当天成功接收的新任务 | 窗口内每日提交之和 |
| `jobs_completed` | 完成翻译 | 当天首次达到 DONE 的任务 | 窗口内每日首次完成之和 |
| `pages_submitted` | 上传页数 | 当天提交 PDF 的完整页数 | 窗口内每日上传页数之和 |

- 请求重试复用访问 `event_id`，不重复算 PV；刷新统计数据不算新的页面访问。
- 健康检查、SSE、任务轮询、静态文件、管理页面不计 PV。
- UUID 代表一个浏览器存储环境，不是真实人数；清除存储、无痕窗口、换浏览器或设备可能重新计数；同一浏览器多人使用也不能区分。
- “访问浏览器”不表示 Chrome/Edge 等浏览器种类；本期不新增 UA 采集。访问事件幂等受去重明细保留窗口限制，不承诺永久防重放。
- 选择部分页翻译时，上传页数仍按完整 PDF 计算，不称为“翻译页数”。
- 同一任务重试、编辑、重新导出不重复增加提交或完成量；同文件重新上传产生新任务，算新提交。
- 今日完成可能来自此前提交的任务，因此不以“今日完成 ÷ 今日提交”计算成功率。
- 新增提交明细不会改写现有统计起始日期，也不把升级前存活任务当作新使用量。

### 4.3 图表与移动端

- 继续使用现有 SVG，不引入图表依赖；七个日期和七个值始终可见，包括 0。
- 数值以适合宽度的紧凑格式显示，选中日期的说明区显示完整数值；较大数值不挤出屏幕。
- 每个日期具有至少 44×44 CSS 像素的交互区域，不能只让细小柱体响应点击。
- 默认选中今天；点按其他日期后高亮其柱体，下方显示完整日期、指标、数值。切换指标保留所选日期。
- 使用可访问的 HTML 按钮与图形一一对应，支持 Tab、左右方向键及 Enter/空格；选中状态有文字和 `aria-pressed`，不只靠颜色。
- 屏幕阅读器可读每个日期和数值；选中说明用温和的 `aria-live`，不在后台刷新时反复播报整页。
- 390px 宽度不出现整页横向滚动。汇总卡片两列排列，最后一个自适应；大屏五列。明细表可在自己的容器内横向滚动。
- 深浅主题均清晰；减少动态效果时不播放柱高过渡。

### 4.4 加载、刷新与时间

- 首次加载显示骨架或加载说明，不把未知值冒充 0。
- 真正无记录时显示 0 和“该时段暂无记录”；统计启用前的日期显示“尚未启用”，不当作观测到的 0。
- `generated_at` 是服务端生成快照的时间，界面标注“数据更新于”，不是浏览器当前时钟。
- 保留 30 秒缓存；页面可见时每 60 秒刷新，窗口重新获得焦点时按过期状态刷新，隐藏时停止定时请求。
- 北京时间跨日后重新获取整个 7 天窗口；一次请求采用同一个服务端 `now`，不能出现“今日日期”和汇总窗口不一致。
- 手动刷新禁用重复点击。刷新失败保留旧数据、旧更新时间，并显示“刷新失败，当前为上次数据”；首屏失败显示重试卡片。

## 5. 公开接口与跨日去重

### 5.1 拟议合同

`GET /api/stats?days=7`：仅允许 7，省略参数也使用 7；其他值返回 422。前后端同次发布，移除旧公开 `total`，不保留任意历史窗口的兼容实现。

```typescript
// 仅说明合同结构；实现时必须从后端 OpenAPI 生成 TypeScript 类型。
type PublicStats = {
  timezone: "Asia/Shanghai";
  since: string;             // 统计功能启用时间，不包含使用明细
  generated_at: string;      // 带时区的 ISO 时间
  period: {
    start_date: string;      // YYYY-MM-DD，含当天
    end_date: string;        // YYYY-MM-DD，含当天
    counts: StatsCounts;     // visitors 是整个窗口的独立浏览器数
  };
  today: StatsCounts;
  daily: Array<StatsCounts & { date: string; available: boolean }>;
};
```

`StatsCounts` 延续五个非负整数字段。`daily` 固定升序七项，统计启用前 `available=false`；启用当天可能只有部分时段，用说明表达，不推算缺失数据。

`POST /api/stats/visits` 保持 UUID 上报和幂等语义。所有统计请求显式使用 `credentials: "omit"`，不携带管理 Cookie、翻译 Key或 MinerU Token；响应 `Cache-Control: no-store`，不设置管理员 Cookie，也不返回用户标识。

### 5.2 查询规则

- 访问、任务、完成和页数从 `analytics_daily` 按起止日期求和。
- 窗口浏览器数查询 `analytics_visit_days` 的 `COUNT(DISTINCT visitor_hash)`，日期限制为今天减 6 到今天。
- 读每日值、窗口值和今日值时使用同一个 SQLite 读取快照，避免并发上报造成互相矛盾。
- 现有每日访客明细清理实际保留今天及此前 7 天，共 8 个日期；本期保留该一个自然日的余量，但查询始终只选 7 天。明细不是永久历史 UV 账本。
- 无新访问时也不能返回过期日期范围；查询以当前时间计算窗口，无记录日补零，历史明细即使尚未清理也不得越界计入。
- 长期每日汇总和现有累计账本继续保留；公开接口不再提供累计字段，也不提供任意历史浏览器窗口查询。

## 6. 管理员页面设计

### 6.1 登录与退出

- 单站点、单管理员角色，只需管理密码；不增加用户注册。
- 密码输入允许密码管理器，显示/隐藏由管理员主动切换；失败统一提示“管理密码不正确或暂时无法登录”。429 单独显示稍后重试。
- 登录后进入明细；会话失效清空敏感查询缓存，回到登录页，不保留已显示的标题/IP列表。
- 管理页固定展示“退出管理”。退出立即清空本地管理缓存并撤销服务端会话，浏览器后退不能恢复明细。
- 管理路由 HTML 设 `Cache-Control: no-store`；浏览器恢复页面或重新聚焦时先遮蔽明细并校验会话，再重新显示，避免旧页面快照暴露退出后的数据。
- 直达明细 URL 未登录时不请求列表。前端路由检查只是体验优化，后端接口必须独立鉴权。

### 6.2 明细布局

```text
提交记录                                         退出管理
已长期留存的提交元数据；正文和文件按保留期清理

标题关键词 [              ]  提交 IP [           ]
提交日期   [起始日期] 至 [结束日期]   查询  重置

符合条件 128 条 · 第 1 页
提交时间 | 论文标题 | 提交 IP | 上传页数 | 当前状态
……
每页 [25 ▾]                           上一页 下一页
```

- 默认查询最近 7 天的提交，管理员可选择更早范围；公开 7 天限制不适用于此受保护页面。
- 提供“最近 7 天／最近 30 天／全部”快捷项；自定义按北京时间日期，结束日期含整天，服务端转为 UTC 半开区间查询。
- 标题默认两行，展开查看完整标题；标记“识别标题”或“上传名回退”。文件名回退只保留去路径、去扩展名后的文字，不同时长期保存一份额外完整文件名。
- 完整 IPv4/IPv6 可换行显示；提供行内复制，复制失败明确提示。没有可靠 IP 显示“未记录”，不能用 `0.0.0.0` 代替。
- 手机改为纵向记录卡，筛选控件单列；不要求在宽表中横向拖动才能看到 IP。
- 状态是最近一次持久化的任务状态，重试后允许变化；“首次完成时间”独立保存，不把“曾完成”和“当前 DONE”混为一谈。
- 标题/IP为空、首次无数据、筛选无匹配、权限过期、网络失败分别给出明确状态；失败不显示虚假空列表。
- 本期不提供内容预览、下载链接或过期任务跳转。长期元数据不能恢复已清理的 PDF。

### 6.3 查询规则

- 标题关键词：去首尾空白，最长 100 字符；按子串匹配，不支持任意 SQL 或正则。`%`、`_` 按普通字符转义。
- IP：本期只支持规范化后的完整 IP 精确匹配，支持 IPv4 和 IPv6，不做模糊地址搜索或网段检索。
- 日期可为空；非法日期、起始晚于结束、非法 IP 返回 422，前端给字段级提示。
- 每页 25 条，可选 50、100；最大 100。服务端默认排序 `submitted_at DESC, job_id DESC`，不允许任意排序表达式。
- 使用页码分页和独立总数查询，同一次读取快照返回 `items/total/page/page_size`。翻页期间新提交可能使位置变化，点击刷新回第一页；本期不声称跨请求冻结快照。
- 不将标题/IP筛选写入浏览器 URL、localStorage 或埋点；筛选经 POST JSON 提交，避免敏感搜索词出现在普通访问日志的查询字符串中。

## 7. 管理接口与鉴权

### 7.1 拟议接口

| 方法与路径 | 用途 | 保护 |
| --- | --- | --- |
| `POST /api/admin/session` | 密码登录，建立 Cookie 会话 | 同源验证、限流 |
| `GET /api/admin/session` | 查询当前会话、获取 CSRF Token | 有效会话 |
| `GET /api/admin/submissions/client` | 核验管理员本次请求的可信 IP，不持久化 | 会话、限流 |
| `DELETE /api/admin/session` | 退出并撤销会话 | 会话、同源及 CSRF |
| `POST /api/admin/submissions/search` | 过滤、分页查询明细 | 会话、同源及 CSRF |

搜索请求为 `title_query/ip/date_from/date_to/page/page_size`；响应为 `generated_at/total/page/page_size/items`。每项仅含第 8 节允许的元数据，不通过复用 `JobOut` 或原始 `jobs.data` 返回额外内容。

所有管理响应设 `Cache-Control: no-store`；接口无有效会话返回 401，不将 API 302 到 HTML。配置未启用管理功能时，管理 API 返回 404，页面显示“本站未开启管理功能”。无权限请求在执行明细 SQL 前终止。

### 7.2 密码与会话

- 新增 `PDFTR_ADMIN_PASSWORD_HASH`，只存部署机 `.env`，不公开在 `/api/config`。提供本地交互生成工具，用隐藏输入生成随机盐的 scrypt 哈希，不在命令行参数或日志中传明文。
- 新增 `PDFTR_SUBMISSION_AUDIT_ENABLED`，默认 false。只有管理员哈希、HTTPS Origin、可信 IP配置和上传告知同时就绪，才允许显式开启采集；配置不完整时启动校验失败，不静默开启。公开聚合统计不受该开关影响。
- 初版 scrypt 参数拟定 `N=32768, r=8, p=1`，单次约需 32 MiB 工作内存；实施时在目标机器测耗时，密码校验最多同时一个，放线程执行，避免阻塞事件循环。哈希格式带参数版本，非法/过大参数启动时拒绝。
- 管理密码至少 16 字符，推荐使用密码管理器生成的随机密码。登录输入限制 256 UTF-8 字节，比较使用恒定时间方法。
- 登录成功生成至少 256 位随机会话 Token；浏览器只收到 Cookie，SQLite `admin_sessions` 仅保存 Token 的 SHA256、创建/到期时间与密码配置版本摘要。
- 使用 `__Host-pdftr_admin` Cookie：`HttpOnly; Secure; SameSite=Strict; Path=/`，不设置 Domain；生产必须 HTTPS。本地验收也使用 HTTPS，不在生产配置中自动降级 Cookie 安全属性。
- 会话固定 8 小时，不自动滑动续期；登录生成新 Token，不把密码或会话写入 localStorage/sessionStorage。刷新页面仍可使用有效 Cookie。
- 更换密码哈希后旧会话全部失效；退出删除对应会话，到期会话定时清理。服务重启不延长会话。
- 管理 API 使用独立客户端，显式设置 `credentials: "same-origin"`，只发同源 Cookie 和 CSRF Header，绝不附带翻译/解析凭据；退出、401 后清空 React Query 管理数据，不做持久化。

### 7.3 同源、CSRF 与限流

- 新增 `PDFTR_ADMIN_ORIGIN`，显式配置部署的 HTTPS Origin；不靠任意客户端 Host 或转发头自动推导可信来源。
- 登录及其他 POST/DELETE 必须为 JSON 请求，`Origin` 必须与配置精确匹配；拒绝缺失、`null` 和其他来源。管理接口不启用跨域凭据 CORS。
- 已登录的 POST/DELETE 还须 `X-CSRF-Token`：服务端从请求中的随机会话 Token 用 `HMAC-SHA256(key=session_token, message="pdftr-admin-csrf-v1")` 派生，URL安全编码后在登录/会话查询响应返回；前端只存在内存，服务端先验证会话，再恒定时间比较派生值。该值与会话绑定、不公开给跨域请求，也不能替代会话 Cookie。
- 同一会话的 CSRF值保持稳定；刷新可通过 GET会话接口重新获取，多标签页互不轮换 Token。重新登录建立新会话时获得新值，退出/到期后旧值无效。GET会话查询不续期，也不写新 Cookie。Cookie 的 SameSite 是附加保护，不替代上述检查。
- 登录拟按可信客户端 IP 限制每 15 分钟 5 次失败，另设全站每分钟 30 次尝试上限；429 附 `Retry-After`。限流在昂贵密码校验之前执行；不将提交明细中的 IP 当作登录身份。
- 单副本初版用带容量上限和过期回收的内存限流器；重启会重置计数，文档说明该限制，不宣称支持多副本共享限流。不可靠的客户端 IP统一进入未知来源桶，不能通过伪造头绕过。
- 管理查询限每会话每分钟 60 次，SQL 使用绑定参数；不记录请求体、密码、Cookie、Token、标题搜索词或完整 IP。
- 所有标题作为文本渲染，不执行 HTML。保留现有 CSP、禁止嵌入与 Referrer-Policy。

## 8. 长期提交元数据

### 8.1 独立账本

新增 `submission_audit`，仍使用现有 SQLite，不新增数据库容器；不通过外键级联随任务 TTL 删除。新会话表与账本分别建模，避免把会话凭据当统计字段。

| 字段 | 类型/约束 | 含义 |
| --- | --- | --- |
| `job_id` | TEXT PRIMARY KEY | 与一次成功接收的任务一一对应 |
| `title` | TEXT NOT NULL | 最多 500 Unicode 字符，识别标题或上传名回退 |
| `title_source` | parsed / filename / unknown | 标题来源 |
| `submitted_at` | UTC 时间，NOT NULL | 初次成功接收任务的时间，不随重试改写 |
| `submitter_ip` | TEXT NULL | 规范化 IPv4/IPv6，未知为空 |
| `ip_source` | trusted_proxy / direct / unknown | 地址来源，便于识别未可靠采集 |
| `page_count` | INTEGER 非负 | 完整 PDF 上传页数 |
| `status` | 任务状态枚举 | 最近持久化状态 |
| `first_completed_at` | UTC 时间 NULL | 第一次 DONE，后续重试不覆盖 |
| `updated_at` | UTC 时间 | 最近元数据更新时间 |
| `record_source` | live / backfill | 新提交或升级补录 |
| `notice_version` | TEXT NULL | 新提交时生效的数据保留说明版本 |

索引：`(submitted_at DESC, job_id DESC)` 和 `(submitter_ip, submitted_at DESC, job_id DESC)`。初期标题子串搜索不引入 FTS，先按日期过滤；数据增长后用实测决定是否增加全文索引。预计每条记录加索引约数百字节到数 KB，这是容量估算，实施后用合成数据测量。

不长期保存正文、摘要、译文、段落、原始模型响应、修改内容、PDF路径、Key、Cookie、浏览器 UUID 或完整 HTTP 请求。识别标题后替换回退名称，不额外保留一份原始上传名。标题移除路径、控制字符，裁剪长度；不能把文件名中的任意目录当作标题。

### 8.2 写入顺序和一致性

1. 上传路由从可信请求上下文生成 `SubmissionContext`（IP、来源、说明版本），传给 pipeline 用例；HTTP 对象不进入领域或存储层。
2. 文件类型、页数、容量、配额和凭据检查通过后，先写临时任务文件，再在同一存储事务中创建任务、首次提交统计与提交账本。失败时回滚数据库并补偿临时文件，不返回 202、不计提交。
3. 上述事务成功后才调用 `pipeline.submit()`。若调度失败，保存可重试的 FAILED 状态，仍属于已经成功接收的一次提交；API返回可识别的任务，不重复创建。
4. fuse 生成 IR 后，通过既有 `paper_title()` 同步更新标题。账本更新必须在进入下一阶段前持久化；标题识别失败采用回退，不增加 LLM请求。已存在 IR 的断点恢复分支同样执行幂等补写，覆盖“IR 已保存、标题尚未入账”时中断的情况；账本更新使用局部 UPDATE/UPSERT，不能用 REPLACE 清空原 IP、提交时间或来源。
5. 后续 `save_job` 与账本状态更新同事务，首次 DONE 写一次完成时间；段落重翻不新增账本。
6. 删除/过期只清短期数据，保留账本。清理失败不删除长期记录，也不把账本当作待重翻任务恢复来源。

现有 `save_job()` 的其他调用不得凭空补造提交 IP；缺失上下文保留 unknown。迁移、测试和新上传使用明确不同入口，避免从任务更新自动制造假提交。

采集关闭期间不会补记完成时间。重新开启后，不能把首次观察到 DONE 的时刻当成停采期间真正的完成时刻；缺少可靠完成时间的历史记录保持 `first_completed_at=NULL`。不得用 `updated_at` 猜测，停采期间上传的任务也不在普通状态更新时自动新增账本。

### 8.3 历史数据

- 已过期且已清除的论文名/IP不能恢复，不从访问浏览器哈希推断 IP。
- 升级时可以在独立迁移事务中为现存任务补录标题、提交时间、页数和状态，标记 `backfill`；提交 IP 为空、说明版本为空，不改写原统计计数。
- 不根据时间相近的代理访问日志猜测提交者，不用当前阅读者 IP 回填。
- 元数据保留说明从发布时生效；历史补录和新记录可在管理页识别。迁移前确认备份与保留说明一致，不能将本设计文档视作已经执行过迁移。

## 9. 提交 IP 的可信链

当前路径为公网 → OpenResty → 宿主机回环 18765 → Caddy → FastAPI。实施前确认公网是否另有 CDN，并记录实际代理网段，不能直接信任请求的第一个 XFF。

设计采用明确的右向左可信代理解析：

1. OpenResty 如有 CDN，只对实际 CDN 公布且核验过的来源网段启用真实地址恢复；没有 CDN 就使用 TCP 对端。拒绝信任任意来源的 `CF-Connecting-IP` 等头。
2. OpenResty 向 Caddy **覆盖** `X-Forwarded-For` 为其已校验的客户端地址，不拼接外部用户提供的链。
3. Caddy 只信任实际 OpenResty 对端地址，开启严格可信链解析；不得默认信任所有私网或 `0.0.0.0/0`。Caddy 继续生成明确的上游代理链。
4. Uvicorn 禁用自动改写客户端地址，由一个统一后端解析器读取原始 TCP peer；只在 peer 属于显式配置的可信代理时解析 XFF，从右向左剥离可信跳数，取第一个非可信地址。
5. 新增 `PDFTR_TRUSTED_PROXY_CIDRS` 配置精确可信来源。Docker 网络地址必须结合实际 Compose 网络确认，不能把某个示例 IP 写死为默认可信；若网段改变需重新验收。
6. 使用 `ipaddress` 校验并规范化；IPv4-mapped IPv6 按 IPv4 统一，支持普通 IPv6。限制头长度和跳数；无效头、错误链或未完成信任配置记 unknown，不把容器 IP冒充提交者。

生产 app:8000 不对公网暴露，web 继续绑定宿主机 `127.0.0.1:18765`。不通过开放后端端口、全信任 Uvicorn 转发头来“修复”IP。

上线前以两条受控网络访问上传测试入口，并伪造外部 XFF 对照验证；只能使用合成 PDF。运维验收仅保留脱敏对照结果，不把完整访客 IP写进仓库或测试报告。提交 IP 表示该请求的网络出口，不等于用户身份。

## 10. 临时内容与长期数据的保留

本设计中的“不留存正文”指不长期留存，保留现有 24 小时阅读、编辑、重翻与下载窗口。不得在页面写“数据库从不保存正文”或“完成立即清除”。

- 过期后清理任务行、段落、修订、原始/背景/导出 PDF、解析结果和 IR；翻译缓存也按保留期清理。
- 清理目录失败应持久化待清理项并重试；增加孤儿目录巡检，避免先删数据库后文件删除失败再无人处理。运行中的任务和未过期目录不能误删。
- 手动删除与共享翻译缓存的关系需明确：当前缓存没有任务归属，本期不得承诺手动删除后立即移除所有共享译文；若需要该保证，应单独增加缓存引用账本或调整缓存隔离。
- SQLite DELETE 属于逻辑删除。实施时评估 `secure_delete`、WAL checkpoint 和安全的空间回收流程，验证性能；不能把逻辑删除等同于底层存储可证明擦除。
- 含正文的完整库备份采用明确短期到期策略；长期备份只含批准的元数据/统计，不含任务、段落、修订、译文缓存或可恢复的旧库页。不能直接复制完整库再只删表行当成净化备份。
- 本轮发现的旧备份仅做清单，不自动删除。实际清理、保留周期变更及恢复演练在实施部署步骤中单独记录。

## 14. 验收标准

### 14.1 统计正确性

- 同浏览器七天内每天访问：每日浏览器各为 1，7 天浏览器为 1；第二浏览器加入后为 2。
- 边界日期、北京时间跨午夜、无新访问、清理前后、重启和并发上报结果正确。
- 今日包含在 7 天内；窗口恰好七项，旧数据不能通过 `days=30/90` 或累计字段公开获取。
- 统计启用前显示未启用；有数据但刷新失败保留旧值与旧时间。
- 原有访问幂等、首次任务完成和重试不重复计数仍通过测试。

### 14.2 管理权限与隐私

- 未登录/过期/退出/密码轮换后，搜索 API 均为 401，不能通过直达 URL、直接调用 API 绕过。
- 其他 Origin、缺失 Origin、非法 CSRF、未知 Cookie、过长密码/查询均有明确拒绝结果。
- 刷新或服务重启后可恢复未到期会话的 CSRF值；同一会话两标签页交替查询/退出行为正确，不因会话查询而互相使Token失效。
- 并发登录受限，限流桶可回收，伪造 XFF不能绕过限流或污染提交 IP。
- 浏览器存储、日志、公开 API、OpenAPI示例和测试报告无真实密码、标题、IP、Key。
- 登录和管理请求不携带翻译/解析 Key；管理导航不增加公开 PV；退出后后退无敏感列表。

### 14.3 记录、迁移与查询

- 上传拒绝无账本；任务首次接收只一条；失败/取消/重试更新原条目。
- 标题解析成功覆盖回退名，解析失败仍可查；IR写入后中断并重试能补齐标题；历史补录 IP为空，不增加旧任务统计。
- 删除任务、TTL清理后账本仍在，正文/文件不从明细接口返回。
- IPv4、IPv6、未知来源、可信/不可信代理与恶意头都覆盖；日期筛选、Unicode标题、特殊通配符、分页同时间排序稳定。
- 使用全合成数据演练迁移幂等、事务回滚、清理失败重试和备份恢复。

### 14.4 UI 与运行成本

- 390×844、桌面、深浅主题下检查卡片、日期/数值、点按、键盘、错误与会话过期。
- 以至少 10 万条合成元数据测日期/IP查询、标题搜索、深页分页和索引占用；在目标机器记录实测，不预先承诺固定毫秒数。必要时依据结果将深页分页改为游标，再更新合同。
- 新增测试每轮设置 60 秒硬超时；完成 Ruff、Pyright、import-linter、前端 typecheck/lint/test/build 与 OpenAPI同步检查。
- 不为纯设计文档增加产品测试。实施时不调用真实用户 Key 做付费翻译验证。

## 15. 发布与恢复

- 本文件本身不触发迁移、生产配置变更或数据清理。
- 实施发布前核对站点告知、管理 HTTPS Origin、实际可信网段和备份清单；生成管理员哈希后安全写部署环境，不进入仓库。
- 按项目要求在构建前、重启前分别硬检查无 running/queued 任务。目标服务器内存较小，前端优先在本地构建，再上传核验并制作运行镜像。
- 发布前在线备份用于短期回退，验证完整性并登记到期时间；不把该完整库列为永久备份。
- 新表采用可重复执行的增量迁移；不删除原有任务/统计表。回退保留新表和账本，不用旧整库直接覆盖而丢弃发布后的提交。
- 若可信 IP验收不通过，不开启正式采集并标记为已完成；优先修正配置，不能先保存容器地址冒充用户地址。
- 停止采集时先将 `PDFTR_SUBMISSION_AUDIT_ENABLED=false`；之后可移除管理配置关闭管理访问。禁用状态不再写入或更新提交账本，不自动删除既有记录。公开统计独立运行。
- 验收报告记录实际 commit、镜像版本、公开字段检查、脱敏鉴权/IP结果和备份期限；不得把设计文档状态当成上线结果。
