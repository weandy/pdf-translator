# 体验改进第三轮：设计

> 日期：2026-10-29
> 来源：用户使用 v0.2.0 后的反馈。
> 范围：全站使用指南、章节跳转高亮、移除“阅读”视图、术语库（管理、导入导出、在翻译中的作用）、网站名称与 logo。

---

## 1. 全站使用指南（替代阅读器提示条）

**依据**：阅读器每次打开都在工具栏下弹出一大块提示，占地方、打断阅读。

**设计**
- 去掉阅读器的提示条和工具栏“说明”按钮（`ReaderTips`、`pdftr.tips.reader.v1` 不再使用）。
- 顶栏右上角加“使用指南”，打开独立页面 `/guide`（按需加载），一页讲清整个流程，左侧是章节目录（窄屏收在顶部）：
  1. 开始前：填两项设置（翻译 API Key、MinerU Token），各自去哪里拿、要花多少钱
  2. 上传与翻译：选文件（可多选）、页码范围、费用与用时预估、排队、取消、重复上传提醒
  3. 阅读：对照 / 译文 / 原文三种显示方式、目录、页码跳转、链接、记住阅读位置
  4. 修改：点段落（或 Tab 键选中、回车）、修改译文、公式占位符、重翻与精修、修改记录与撤回；灰色虚线框、黄色点线框是什么意思
  5. 术语库：添加、导入导出、在阅读器里查看本文术语、改译法后重翻
  6. 下载：中文版与双语对照、断点续传
  7. 保留期限与隐私：服务器只留 24 小时；哪些数据只在浏览器里
  8. 常见问题：解析失败、某段没翻好、费用怎么算、怎么自己部署（Docker）
- 首页三步说明下加“完整使用指南”链接。

## 2. 章节跳转时高亮对应标题

**依据**：点目录跳过去后，不容易一眼看到是哪一行；而点译文段落时原文对应位置有底色，定位很方便。

**设计**
- 点目录某一项：滚到位置后，原文与译文上对应的标题块同时显示与“选中”相同的底色，约 2 秒后淡出（`flash` 样式，尊重“减少动态效果”设置：不做淡出，直接 2 秒后去掉）。
- 书签标题对不上任何标题段落时，后端在同一页、离书签位置最近（上下 60 点内）的标题块兜底，尽量让每一项都有可高亮的段落。

## 3. 移除“阅读”视图

**依据**：用户反馈效果不好，决定去掉。

**设计**
- 显示方式只保留“对照 / 译文 / 原文”。窄屏（< 760 px）默认“译文”单页、适应宽度，可用缩放按钮或双指放大。
- 删除 `ReadingView` 及其样式；后端删除只给它用的 `GET /api/jobs/{id}/blocks/{block_id}.png` 与 `block_crop`、`BlockOut.latex`（若无他用）。
- 手机上段落编辑仍从底部弹出。

## 4. 术语库

### 4.1 独立页面与管理

**依据**：现在是一个对话框，导入、手动添加、全部词条挤在一起；条目多时全部渲染，不能批量操作。

**设计**
- 术语库改为独立页面 `/glossary`（顶栏“术语库”进入），上方是工具条：搜索（英文、译法、说明）、排序（最近修改 / 英文 A–Z）、“添加”“导入”“导出”。
- 列表：每行英文、译法、说明，点击行内直接编辑（回车保存、Esc 取消）；可勾选多行批量删除；删除后提示“已删除 N 条”并可撤销。
- 每次显示 100 条，“再显示 100 条”加载更多；顶部显示总数与筛选后的条数。

### 4.2 导入导出

**设计**
- 导入来源：选文件、拖入文件，或直接粘贴文本（如从表格里复制的两列）。
- 识别后分三组确认：
  - **新词条**：默认全部勾选；
  - **译法不同**：并列显示“原来 / 导入的”，逐条选保留哪个（默认用导入的），可一键“全部保留原来的”；
  - **完全相同**：直接跳过，只显示条数。
- 导出：CSV（Excel 可直接打开）、TSV、JSON，三种格式都能再导入回来。

### 4.3 本文术语（翻译中的作用）

**依据**：用户看不到这篇论文到底用了哪些术语，发现译法不对时只能逐段改。

**设计**
- 阅读器工具栏加“术语”，打开右侧面板，列出这篇论文用到的术语：英文、译法、来源（我的术语库 / 本文自动抽取 / 公共词库）、出现在几段。
- **一致性检查**：已翻译的段落里原文出现了该术语、但译文里没有推荐译法的，标“N 段可能不一致”，排在最前。
- 点一个术语：译文里出现它的段落临时高亮（与章节跳转相同的底色），并可“上一段 / 下一段”逐个跳转。
- **改译法**：输入新译法 → 保存到我的术语库 → 提示“重翻用到它的 N 段”，确认后分批重翻（每批 20 段，显示进度），每段照常记入修改记录、可撤回，费用计入任务。自动抽取和公共词库的术语可“加入我的术语库”。
- 接口：
  - `GET /api/jobs/{id}/terms` → `[{source, target, origin, segment_ids}]`。来源与译法按建任务时的用户术语计算。
  - “可能不一致”在前端计算：要按浏览器里最新的术语库和当前译文（重翻、手动修改后）实时算，放在后端会算两遍。
    译法有多个写法（“A；B”）时任一即可，括号里的注释与空白不计。手动改过的段落不参与重翻。
  - 实测（ResNet）：模型把 baselines 有时译“基线”、有时译“基准”，shortcuts 有时译“捷径连接”、有时译“直连边”，都被标了出来。
  - `POST /api/jobs/{id}/retranslate`：`{segment_ids（≤ 20）, quality, user_terms}`，一次重翻多段（与整篇翻译相同的批处理），返回新段落。

## 5. 网站名称与 logo

“PDF 保版式翻译”不好听。名称按“品牌名 + 说明”组织，说明定为“在线可编辑的 PDF 翻译”，品牌名由用户选定后再设计 logo（给 2–3 版 SVG 挑选），同时更新标题、顶栏、网站图标、README。**待用户确定名称。**
